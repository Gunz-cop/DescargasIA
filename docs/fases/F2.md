## Instrucciones

### `resolve.ts` — matcher local, sin IA

Normaliza (minúsculas, sin acentos, espacios colapsados, `3060ti` → `3060 ti`, quita `ANGLE (...)` y los identificadores hex de las cadenas de WebGL), tokeniza y puntúa contra `name` + `aliases`.

Devuelve `{ gpu, score, candidates[] }`:
- score alto → match directo;
- score medio → hasta 3 candidatos para un "¿quisiste decir…?";
- sin match → `gpu: null`, y ahí entra la vía de escape (el usuario teclea la VRAM, o F6 consulta a la IA).

**La IA nunca es el primer recurso.** El matcher local debe resolver la mayoría de los casos sin red.

### `estimate.ts` — las fórmulas

```
weights   = paramsB * 1e9 * bpw / 8
kvCache   = 2 * numLayers * numKvHeads * headDim * ctxTokens * kvBytes   // kvBytes: f16=2, q8=1
overhead  = 0.6 GB (runtime CUDA/Vulkan/Metal) + 5 % de weights (activaciones)
required  = weights + kvCache + overhead
```

Tres modos, evaluados en orden:

1. **GPU completa** — `required <= vramGb * 0.92`. El 8 % restante queda para el escritorio y el compositor.
2. **Offload parcial** — cuántas capas caben en VRAM, el resto en RAM. Veredicto "funciona con ajustes" y aviso de caída de velocidad.
3. **CPU o memoria unificada** — Apple Silicon usa `ramGb * 0.75`; x86 sin GPU usa RAM del sistema menos 3 GB de SO.

**Velocidad (roofline de ancho de banda):** `tok/s ≈ bandwidthGbs / modelSizeGb * eficiencia`, con 0,7 en GPU y 0,5 en CPU; en MoE se usa `activeParamsB`. Se devuelve **siempre como rango**, nunca como cifra exacta: el consumidor está obligado a rotularlo como estimación.

**Veredictos:** `holgado` / `funciona` / `justo` / `no-cabe`, cada uno con su razón (`vram`, `contexto`, `sin-gpu`) y la **mejor cuantización recomendada** = la de mayor calidad que entra con margen.

### `recommend.ts`

Ordena el catálogo para unas specs dadas y agrupa por caso de uso: chat general, código, razonamiento, resumen de documentos.

### Tests obligatorios (`node --test`)

Casos dorados — estos números son el contrato del producto:

- **`RTX 4060 Laptop` (8 GB) + Llama-3.1-8B-Q4_K_M → cabe a 4k de contexto y NO cabe a 32k.** Es el caso que rompe a las herramientas rivales; si este test no existe, la fase no está hecha.
- `M2 Pro` 16 GB unificada.
- `RTX 3090` 24 GB.
- iGPU + 16 GB de RAM → debe caer a CPU-only.
- `RTX 4090` + un modelo de 70B → offload parcial.
- Resolver: **25 cadenas escritas como las escribe un humano** → GPU esperada, incluyendo al menos una cadena cruda de `WEBGL_debug_renderer_info`.
- **Paridad de i18n:** `sv` e `it` tienen exactamente el mismo conjunto de claves que `es` en `src/i18n/ui.ts`. El fallback de `useTranslations` es solo de runtime, así que sin este test la deriva pasa inadvertida.

## Riesgos conocidos

- **Tentación de ajustar las constantes hasta que dé "bonito".** Las constantes (0,92 de VRAM utilizable, 0,6 GB de overhead, 0,75 de memoria unificada, eficiencias de 0,7/0,5) son aproximaciones razonadas. Van en un único bloque nombrado y comentado, no repartidas por el código, para que se puedan revisar de una sola lectura.
- **Precisión falsa.** Devolver "23,7 tok/s" da una impresión de exactitud que el método no sostiene. Rango siempre.
- **Acoplarse al formato de los datos de F1.** El motor recibe objetos ya cargados; no lee archivos. Así los tests corren con fixtures y F6 puede embeberlos en el Worker.
