# F6 — validación integral editorial, UX, SEO y seguridad

**Issue:** [#45](https://github.com/Gunz-cop/DescargasIA/issues/45)
**Base auditada:** `origin/main@dcf9a9c37e71df457b7b92b176c11c6ad6d0fbe5`
**Rama:** `codex/issue-45-f6-validacion-integral`
**Fecha:** 2026-08-28

## Resultado

La fase no se declara completamente resuelta. El build y los contratos
automáticos pasan, se corrigieron seis grupos de fallos dentro del alcance y se
versionó evidencia para tres problemas que requieren una decisión de Codex:

- [#87](https://github.com/Gunz-cop/DescargasIA/issues/87): las políticas de
  privacidad/cookies no son compatibles con la carga actual de scripts
  publicitarios de terceros;
- [#88](https://github.com/Gunz-cop/DescargasIA/issues/88): las respuestas HTML
  y `/r` no llevan cabeceras defensivas, aunque las APIs sí;
- [#89](https://github.com/Gunz-cop/DescargasIA/issues/89): los dos canales
  móviles declarados para Microsoft Copilot devuelven 404 y la sustitución
  posible parece corresponder a Microsoft 365 Copilot, una identidad que F6 no
  debe cambiar por su cuenta.

Por esos blockers, el PR usa `Refs #45`, no `Closes #45`.

## 3. HTML, SEO técnico y rutas generadas

Una inspección independiente de `dist` analizó las 202 páginas HTML:

- 201 indexables tienen exactamente un canonical y una descripción no vacía;
- los 536 bloques JSON-LD se parsean;
- las 152 fichas que corresponden exactamente a los slugs localizados tienen
  `SoftwareApplication`, `BreadcrumbList` y `FAQPage`;
- las 5 guías tienen `Article` y `BreadcrumbList`;
- no hubo errores de metadatos ni de schema en esa matriz.

El sitemap contiene 201 URLs únicas: incluye `https://fuenteai.com`, 1 guía ES
y 4 SV; no incluye `/r`, `/md/`, el alias `/es` ni guías IT inexistentes. El
índice de sitemap, `robots.txt`, `_redirects` y `_headers` concuerdan con ese
contrato. El alias `/es` → `/`, el 301 `/sitemap.xml` →
`/sitemap-index.xml`, el bloqueo de `/r` y el `noindex` de `/md/*` son
comportamientos intencionales documentados, no fallos.

`links:audit` verificó reciprocidad canonical/hreflang, destinos generados,
ausencia de huérfanas y enlaces internos. Sus cinco avisos están clasificados
en §2 y no se promovieron artificialmente a errores.

## 4. Revisión visual y accesibilidad

Se sirvió `dist` con `wrangler dev --local --port 8788` y se inspeccionó HTML
renderizado, no sólo JSON, con viewport de 360 × 800 y 1440 × 900.

Muestra reproducida:

| Producto | Rutas |
|---|---|
| ES | `/`, `/es/ollama`, `/es/guias/descargar-chatgpt-para-windows` |
| SV | `/sv/ollama`, `/sv/guias/kora-ai-lokalt` |
| IT | `/it/grok` |
| Funnel | `/r?t=grok&p=ios&l=it` y error `/r?t=missing&p=web&l=sv` |

En la muestra no hubo overflow horizontal. Nombre, dominio, tipo de canal, CTA,
no-installer cuando aplica, FAQ, fuentes y alternativas son reconocibles. Las
fichas presentan los tres schemas esperados y las guías los dos propios de una
guía. La portada tiene `main`, navegación y footer; no se detectaron imágenes
sin `alt` ni botones sin nombre accesible. La hoja compilada contiene tres
reglas `prefers-reduced-motion` y los estilos globales definen foco visible.

Limitación del navegador: el envío sintético de `Tab` del controlador no movió
`document.activeElement` fuera de `body`; por eso no se afirma una prueba
completa del orden de tabulación. Se verificaron semántica, nombres accesibles y
CSS de foco, pero queda explícita esta limitación manual.

### Fallos UX corregidos

1. El título de alternativas producía texto accesible concatenado
   (`esistono anche6`). Se añadió un espacio semántico en
   `src/pages/[lang]/[slug].astro`; después del build devuelve
   `Se ti serve Grok, esistono anche 6 alternative reali`.
2. `/r` localizaba el contenido, pero mantenía `<html lang="es">` en IT y SV.
   Ahora sincroniza `document.documentElement.lang` con el idioma saneado. La
   reproducción IT devuelve `lang=it`, copy italiano, destino oficial visible y
   `noindex`.

No se alteraron el retraso, LinkZip, la validación del destino, los eventos ni
la apertura del CTA de `/r`.

## 5. Contenido, claims y fuentes

### Fallos reproducibles corregidos

- **Grok IT:** la ficha exigía cuenta X y negaba apps autónomas. La documentación
  actual de xAI declara `grok.com`, apps Grok para iOS/Android y un account xAI
  que puede usar email, Google, Apple o X. Se corrigieron ficha y fuentes base.
- **Ollama ES/SV/IT:** el contenido afirmaba local/offline para todo Ollama. La
  documentación oficial distingue modelos descargados de modelos cloud,
  cuenta necesaria para cloud y un modo solo local que desactiva cloud y web
  search. Se corrigieron los tres productos y se añadieron las fuentes
  oficiales. En ES también se eliminaron umbrales genéricos 8/16/70B que la
  propia spec de hardware desaconseja.
- **Mistral Vibe ES:** se reemplazó la ventaja genérica de «privacidad/GDPR» por
  hechos acotados: alojamiento UE por defecto, transferencias posibles según
  función y entrenamiento por defecto en Free/Pro/Education salvo opt-out.
- **Character.AI ES:** la FAQ dejó de certificar que una descarga «es segura»;
  ahora enseña a comprobar editor y canal.
- **Stable Diffusion ES:** se quitaron atribuciones no demostradas sobre lo que
  contienen paquetes de terceros; el criterio queda limitado al origen que el
  catálogo sí puede verificar.

Las mismas correcciones aparecen en HTML, `dist/md/**`, `llms-full.txt` y el
catálogo derivado porque todos salen de las mismas colecciones. El build de
agentes y sus tests pasan.

### Verificación de canales externos

Se probaron los 187 destinos únicos de `tools-base.platforms` con `HEAD` y
fallback `GET`, redirects habilitados, timeout de 15 s y CA del sistema:

- 176 respondieron 2xx/3xx;
- 5 bloquearon la auditoría con 403/429 (`leonardo-ai`, `mistral-vibe`,
  `claude`, `devin-desktop`, `scispace`): limitación externa, no evidencia de
  enlace roto;
- 4 no pudieron clasificarse por exceso de cabeceras en la cadena externa
  (`gemini`, `ltx-studio`, `descript`, `krea-ai`): limitación del cliente;
- 2 devolvieron 404 reales: Microsoft Copilot Android/iOS, blocker #89.

El primer intento sin `node --use-system-ca` falló en los 187 destinos con
`UNABLE_TO_VERIFY_LEAF_SIGNATURE`; no se confundió ese problema del entorno con
187 enlaces rotos.

## 6. Seguridad, privacidad y superficies para agentes

### Comportamiento verificado

- un POST a `/api/hw/parse` con `Origin: https://evil.example` devuelve 403
  `origin_not_allowed`;
- la respuesta de API incluye `Cache-Control: no-store`, `nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy` y `Permissions-Policy`;
- los tests MCP/A2A rechazan origen ajeno, payload grande, content-type erróneo
  y JSON-RPC inválido; los fallos controlados no se convierten en 500;
- HTML y Markdown varían por `Accept`; `/md/*` lleva `X-Robots-Tag: noindex`;
- catálogo, OpenAPI, llms, Agent Card, MCP card, A2A y dos Agent Skills se
  generan y pasan tests desde las mismas colecciones humanas;
- no se publican metadatos OAuth porque no existe un servidor OAuth. Es una
  omisión intencional documentada, no una carencia que F6 deba maquillar.

### Blockers

- **Privacidad/publicidad — #87.** Las políticas absolutas no se pueden
  sostener mientras `AdSlot.astro` cargue scripts remotos en portada, fichas y
  `/r`. F6 no decide base legal, CMP ni redacción contractual.
- **Hardening global — #88.** Las respuestas HTML y `/r` no tienen las
  cabeceras defensivas presentes en la API. CSP, referrer y anuncios están
  acoplados; añadir una política a ciegas puede romper el producto o el funnel.
- **Canales Copilot — #89.** Dos 404 confirmados requieren decidir si la ficha
  migra a Microsoft 365 Copilot o conserva la identidad del asistente personal.
